部署教程v2.1.0

先选路线，再起容器

FilmShelf 不存片，它负责「找片 → 转存 → 整理 → 让 Emby 看到」。转存和整理有两种做法，部署前先选一种，后面的配置完全不同。

路线 A · 推荐

有 Cloud Media Sync

CMS 负责转存、整理、生成 strm、刷新 Emby；FilmShelf 只做调度。

  • 需要：CMS + 115 + Emby
  • 适合：装完就想在 Emby 看
  • 成熟度：稳定
路线 B · 实验性

没有 CMS

FilmShelf 直接调 115 接口：接收 → 识别 → 建目录 → 移动/重命名。

  • 需要：115 + 一个 115→Emby 挂载
  • 不生成 strm，不刷新 Emby
  • 适合：已有 115 挂载 / 只整理网盘
路线 B 只把文件整理进 115，不会写 .strm、也不会通知 Emby。如果你的 Emby 没有挂载 115，媒体库里不会出现新片——想要「装完就能看」，请走路线 A。

两条路线都要做的准备

需要说明
能跑 Docker 的 NAS / 服务器群晖、威联通、fnOS、Linux 都行
115 网盘账号转存必须用你自己的账号
数据目录挂到容器 /data，必须持久化（配置、Cookie、日志）
端口默认 8790
docker pull caowenrui/media-suite:2.1.0

路线 A：有 CMS

1. 先把 CMS 准备好

CMS 要已经能正常转存，并且配好了 115、媒体目录、strm 输出和 Emby。记下 CMS 地址与 API Token（Cloud Media Sync 默认 cloud_media_sync）。

FilmShelf 调用的是 CMS 的 POST /api/cloud/add_share_down?token=...，body 为 {"url":"115分享链接"}。

2. 起容器

services:
  media-suite:
    image: caowenrui/media-suite:2.1.0
    container_name: media-suite
    restart: unless-stopped
    ports:
      - "8790:8790"
    environment:
      TZ: Asia/Shanghai
      DATA_DIR: /data
      TRANSFER_BACKEND: cms
      CMS_BASE_URL: http://192.168.1.10:9527   # 改成你的 CMS 地址
      CMS_API_TOKEN: cloud_media_sync          # 改成你的 Token
    volumes:
      - ./data:/data
docker compose up -d

CMS_BASE_URL 必须是容器里能访问到的地址，不要写 127.0.0.1；显式写 cms 比 auto 稳。

3. 首次配置

打开 http://你的NAS:8790，admin/admin 登录并改密 →「设置 → 115 授权」扫码 →「设置 → 入库」确认 CMS 地址 + Token →（可选）填 Emby。

4. 验证

搜一部片 → 转存 → 事件页出现「已提交」→ CMS 任务里能看到这条分享 → CMS 生成 strm 后 Emby 刷新出现该片。

路线 A 常见坑

现象原因 / 处理
CMS 不可达容器访问不到该地址：换 NAS 局域网 IP，确认端口
401 / token 错误CMS_API_TOKEN 与 CMS 配置不一致
转存成功但 Emby 没片CMS 的媒体目录与 Emby 库路径不一致
提示分享失效FilmShelf 的 115 Cookie 过期，重新扫码

路线 B：没有 CMS

1. 起容器

services:
  media-suite:
    image: caowenrui/media-suite:2.1.0
    container_name: media-suite
    restart: unless-stopped
    ports:
      - "8790:8790"
    environment:
      TZ: Asia/Shanghai
      DATA_DIR: /data
      TRANSFER_BACKEND: 115direct
      DIRECT115_DRY_RUN: "1"   # 先 1 看规划，确认后改 0
    volumes:
      - ./data:/data
后端取值是 115direct，不是 direct115。写错会回退到 CMS，然后报 CMS 不可达。

2. 授权 115

「设置 → 115 授权」扫码，Cookie 会写到 /data/cookie.txt。没有它，内置直转不可用。

3. 先 dry-run，再真整理

DIRECT115_DRY_RUN=1 时只接收 + 规划，不移动文件。看日志里的规划路径没问题后，改成 0 重启，才会真正移动/重命名。

4. 它会整理成什么样

Movies影视/
  4K电影/
    D-沙丘-2021/沙丘.2021.mkv
  剧集/
    剧名-2024/Season 01/剧名.S01E01.mkv

5. 让 Emby 看到（关键）

FilmShelf 不写 strm。用 CloudDrive2 / Alist / rclone 把 115 的 Movies影视 挂到 NAS，Emby 媒体库指向挂载点；没有挂载就先只在 115 里整理，Emby 不会出现新片。

现象原因 / 处理
显示成功但 115 没动DIRECT115_DRY_RUN 还是 1，改成 0 并重启
